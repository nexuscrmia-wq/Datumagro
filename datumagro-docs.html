Introdução

Visão Geral do Sistema

DatumAgro é uma plataforma SaaS de gestão pecuária multi-espécie. O backend é um serviço Django REST Framework hospedado no Railway; o app é Flutter offline-first com banco local Drift/SQLite. Toda a comunicação é autenticada via JWT (SimpleJWT).

AuthSimpleJWTAccess 24h · Refresh 30d · ROTATE_REFRESH_TOKENS · Blacklist on logout
MobileFlutter 3Dart, Drift (SQLite offline), flutter_secure_storage, flutter_map

O sistema suporta 5 espécies: BOVINOS_CORTE, BOVINOS_LEITE, SUINOS, EQUINOS, OVINOS_CAPRINOS. Campos, categorias e configurações do app variam por espécie.

Segurança

Autenticação JWT

O sistema usa SimpleJWT. Todos os endpoints protegidos exigem o header Authorization: Bearer <access_token>. O Flutter gerencia o ciclo de vida dos tokens automaticamente.

Fluxo de tokens
TokenDuraçãoComportamento
Access Token24 horasEnviado no header em toda requisição autenticada
Refresh Token30 diasArmazenado em flutter_secure_storage; usado para renovar o access token
Auto-refreshAutomático_authenticatedRequest() no api.dart: ao receber 401, chama refreshToken() e retenta a requisição original uma vez
BlacklistOn logout/deleteAo fazer logout ou excluir conta, todos os refresh tokens são adicionados à blacklist do SimpleJWT
ROTATE_REFRESHAtivoCada refresh emite um novo refresh token (rotação automática)
Endpoints de autenticação
MétodoCaminhoDescrição
POST/api/usuarios/login/Login principal — retorna access+refresh+tipo_especie+status_assinatura
POST/api/token/refresh/Renova access token com refresh token válido
POST/api/usuarios/registrar/Cria Usuario + Cliente + Propriedade padrão; envia email de boas-vindas
POST/api/usuarios/me/alterar_senha/Troca senha (requer senha atual)
DELETE/api/usuarios/me/excluir_conta/LGPD: anonimiza email (sha256), desativa conta, revoga todos os tokens
Arquitetura

Multi-tenancy

Cada recurso do sistema pertence a um Cliente. Todo ViewSet filtra automaticamente pelo cliente do usuário autenticado. Não há risco de vazamento de dados entre tenants.

Hierarquia de acesso
Papeltipo_usuarioAcesso
ProprietárioPROPRIETARIOAcesso total: todas as propriedades do cliente, CRUD completo, gerencia equipe e plano
GerenteGERENTEAcesso a todas as propriedades; pode criar/editar dados; não gerencia plano
FuncionárioFUNCIONARIOAcesso restrito às propriedades no M2M usuario.propriedades; permissões granulares via JSONField

Armazenadas como JSONField em Usuario: can_view_animais, can_edit_animais, can_view_financeiro, can_edit_financeiro, can_view_relatorios, can_manage_usuarios, can_delete_dados, can_manage_lotes, can_view_vacinas, can_edit_vacinas, can_view_alertas, can_view_propriedades.
Cadeia de lookup de cliente (3 níveis)
Toda função que resolve o cliente do usuário segue essa ordem: 1. M2M user.propriedades → propriedade.cliente · 2. Cliente.objects.filter(email_contato=user.email).first() · 3. Cliente.objects.first() (se count==1 — fallback single-tenant). Implementado em BaseViewSet._get_user_cliente, _get_user_cliente_sync, _get_cliente_equipe e IsImportacaoInternacional.

Arquitetura Offline-First

O app funciona sem conexão. O banco local Drift (SQLite) é a fonte de verdade no dispositivo. Alterações são enfileiradas e sincronizadas com o servidor quando a conexão volta.

Componentes
ComponentePapel
Drift (SQLite)Banco local no dispositivo; replica os principais modelos (Animal, RegistroPesagem, etc.)
SyncServiceMonitora conectividade; ao reconectar, envia fila de operações para POST /api/cadastros/sync/
Fila de operaçõesCada CRUD offline é salvo como operação pendente: {tipo, dados, timestamp}
Delta sync endpointRecebe operações do cliente, aplica no servidor, retorna mudanças do servidor desde o último timestamp
flutter_secure_storagePersiste tokens JWT, info do usuário, versão de update dispensada — sobrevive reinicializações
Endpoint de sincronização
MétodoCaminhoPermissãoDescrição
POST/api/cadastros/sync/IsAuthenticatedRecebe lista de operações offline; aplica creates/updates/deletes; retorna mudanças do servidor desde last_sync

Flutter Mobile

Tela — Login

Ponto de entrada do app. Autentica o usuário e direciona para onboarding ou dashboard conforme o status da conta.

Fluxo principal
  • Campos de email e senha com validação; botão "Entrar" chama ApiService().login()
  • Fallback offline: se há token armazenado e sem conexão, navega direto para /dashboard
  • Se status_assinatura == PENDENTE → redireciona para /onboarding
  • Se status_assinatura == ATIVO → redireciona para /dashboard
  • Tokens (access + refresh) salvos em flutter_secure_storage

Telas — Animais

Três telas interligadas: lista do rebanho, formulário de cadastro/edição e detalhe completo com 5 abas.

Lista do Rebanho (AnimalListScreen)
  • Exibe animais do banco local Drift em tempo real (sem esperar API)
  • Busca por brinco/nome; chips de filtro por sexo e categoria
  • Scanner QR Code para localizar animal diretamente por brinco
  • FAB "+" visível somente se can_edit_animais = true
  • SyncService sincroniza automaticamente ao reconectar
Formulário de Animal (AnimalForm)
  • Modo criação e edição; campos adaptados por espécie via _EspecieConfig
  • Campos: brinco, nome, espécie, sexo, categoria, raça (dropdown + campo livre quando "Outra/Mestiço"), data nascimento, peso, status, pai (lookup por brinco), mãe (lookup por brinco), piquete
  • Ao salvar: grava no Drift local + enfileira operação de sync
  • Após criação: navega direto para AnimalDetailScreen

Tela — Romaneio

Calculadora de romaneio de pesagem para venda de gado. Calcula arrobas e valor total por animal e gera PDF oficial via backend.

Funcionalidades
  • Seção de configuração: preço da arroba (R$), nome da fazenda, vendedor, comprador
  • Banner verde com totais em tempo real: qtd animais · total kg · total arrobas · valor total (calculado localmente sem API)
  • Lista dinâmica de animais: por linha — campo brinco, campo peso (kg), exibição de arrobas (peso/30), botão remover
  • Botão "Adicionar Animal" insere nova linha
  • Botão "Calcular Romaneio" envia ao servidor e exibe painel de resultado
  • Botão PDF (ícone): chama cálculo com gerar_pdf=true; backend retorna PDF base64 via WeasyPrint; botão de copiar/exportar aparece
  • Painel de resultado: data/hora, resumo por animal (brinco, raça, kg, arrobas, R$), totais
